# Damage photo fixtures

## Synthetic images (automated tests)

`synthetic_1.jpg`, `synthetic_2.jpg`, and `synthetic_3.jpg` are generated by
`python fixtures/generate_image_fixtures.py`. They are simple PIL car silhouettes
with colored damage markers.

**These will NOT produce meaningful zero-shot detections.** Automated tests only
assert that the Vision Agent returns a schema-valid `VisionOutput` without
crashing. Do not treat confidences from synthetic images as real signal.

## Manual verification (real photos) — not automated

To sanity-check the Vision Agent with meaningful detections / severity / VQA
answers (same live style as Slices 1–2):

1. Drop 2–3 real car-damage photos into this directory under `real/`, e.g.:
   - `fixtures/images/real/photo1.jpg`
   - `fixtures/images/real/photo2.jpg`
2. Do **not** commit real customer photos. Public-dataset or your own photos
   only. This directory is intentionally empty in the repo.
3. With `docker compose up` running and clauses ingested:

```bash
curl -X POST http://localhost:8000/claims \
  -F "policy_pdf=@fixtures/sample_policy.pdf" \
  -F "estimate_pdf=@fixtures/sample_estimate.pdf" \
  -F "narrative=Front-end collision; please review damage photos." \
  -F "damage_photos=@fixtures/images/real/photo1.jpg" \
  -F "damage_photos=@fixtures/images/real/photo2.jpg"
```

4. Poll `GET /claims/<claim_id>` and inspect `result.vision`
   (`detections`, `severity_tier`, `vqa_answers`, `low_confidence`).

Images are **optional** on `POST /claims`. A claim with no photos completes with
`result.vision = null`.
